# Internship Plan

Living tracker for the DHL Dubai IT/BPU internship. Updated as the internship
progresses. Contains no confidential DHL information — see `CLAUDE.md` for the rules.

## Current stage

- **Day:** 2
- **Current team:** Infrastructure
- **Status:** Introductions complete (Day 1). Now sitting with the Infrastructure team
  and being shown how ticket handling works from their side.

## What I have learned so far

- IT/BPU is organized into three teams: **Infrastructure**, **Applications**, and
  **Support & Network**.
- Employees submit IT issues as tickets.
- IT staff open tickets, investigate, document a solution, and resolve/close them.
- Some tickets are expected to be resolved within one or two days (heard informally —
  not a confirmed policy).

## What I am currently learning

- How the Infrastructure team's day-to-day work is structured.
- What a ticket dashboard looks like and how tickets move through it conceptually.
- How to think about IT problems the way a junior IT employee would.

## Questions to investigate (not yet answered — do not assume answers)

- What is DHL's actual SLA / priority structure? (unknown — explicitly not invented)
- How are tickets assigned to a specific team?
- What happens when a ticket can't be resolved by the first team it reaches?
- How does escalation actually work here?
- What tools does each team use day to day?
- How do Infrastructure, Applications, and Support & Network hand off work to
  each other?

## Planned future topics (by team, roughly in rotation order)

1. **Infrastructure** (current) — servers, cloud, VMs, storage, identity/access,
   backups, monitoring, availability, disaster recovery.
2. **Applications** — business applications, APIs, databases, integrations,
   deployments, authentication, application monitoring, software lifecycle.
3. **Support & Network** — ticketing in depth, escalation, SLA, Wi-Fi, LAN/WAN, VPN,
   DNS, DHCP, routers/switches, IP addressing.

## Daily learning strategy

- Use the 10-part topic structure defined in `CLAUDE.md` for any topic studied in
  depth (what is it → ELI10 → technical → business need → owning team → what can go
  wrong → troubleshooting → university connection → practice exercise → question to
  ask).
- Log each day in `daily/day-XX.md` and in the app's Daily Log page.
- After any team interaction, note 2–3 intelligent questions for next time in the
  Questions to Ask list.
- Record any real involvement (not just observation) honestly in the CV Achievement
  Tracker, using the Observed → Learned → Assisted → Participated → Performed → Built
  → Implemented scale.
- Practice with the Ticket Simulator regularly to build troubleshooting instincts
  ahead of doing it for real.
